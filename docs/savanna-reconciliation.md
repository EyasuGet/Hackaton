### Initial proposed changes — disposition recorded below

1. **Keep the technology and behaviour foundations:** TypeScript/React/Fastify/PostgreSQL/Compose, small feature modules, inward dependencies, user isolation, accessible chat, permission-filtered citations, explicit consent, useful tests and author-led standards/spec review. Nothing inspected requires a stack rewrite.
2. **Separate starter demonstration from production integration:** use the supplied static pages as the real supplied demo host, not a lookalike. Keep our backend and a clearly labelled, server-controlled synthetic identity mode. DOM learner names, course attributes and captured tokens remain untrusted. Live ALX SSO/roster/API integration stays a distinct unresolved production adapter, not an invented capability. Any change to T3-004-B/T3-026 acceptance and the final release gate requires approval and clear organiser acceptance, not just renaming a mock as production.
3. **Use a small approved lesson corpus:** T3-005-A/B can import only the actual authored concept content with version/section provenance, excluding dashboard/profile/navigation data. Do not build a general crawler or send an entire page to an AI provider. Exact import boundaries and content reuse approval are still required; one captured lesson is not a full curriculum or an Amharic corpus. Before hosting a demo copy, review/redact captured profile fields and form tokens into synthetic fixtures and record the minimal changes; do not republish the capture blindly.
4. **Make deployment and the explanatory deck explicit:** demonstrate the assistant inside a hosted starter page and document the real limitations. Keep the local reproducible installation and conformance evidence. Serving the demo over controlled HTTP(S), rather than treating a `file://` page as a trusted authenticated origin, is a proposed implementation setup to test—not evidence that microphone, iframe or screen capture works today.
5. **Resume model investigation without assuming sponsorship:** the replaceable provider interface and deterministic FAQ can progress independently. Evaluate available candidates with bilingual examples and native speakers; no cloud call, paid provisioning or private-data upload is authorised by these meeting notes.
6. **Do not shrink baseline scope silently:** Telegram/SMS, careers, voice, human help and capture remain required under the existing spec until an explicit requirement amendment is obtained. The same applies to accessibility evidence, private-data isolation and real-provider proof. Optional web research/employer work remains deferred.
